---
title: Review release notes
cues:
- the requester asks what is wrong with draft release notes
- the requester asks whether release notes are ready to publish
goal: A list of the problems in the draft release notes that would mislead or fail a reader, each tied to the entry it concerns, with the draft itself unchanged.
knowledge:
- change-list
- breaking-change
- section-order
- entry-format
- audience-register
- security-fixes
guides:
- house-style
handoffs:
- task: draft
  applicability:
  - When the requester asked for the problems the review finds to be fixed, and writing the notes is not already on this route
---

Read the whole draft against the change list before judging any entry, and ask
the requester for the change list when none came with the draft. Report each
problem with the entry it concerns and what it would cost the reader, such as a
missing or misfiled change, an entry the change list does not support, an effect
described in the builders' terms, or an entry out of order.

Do not edit the draft; the review reports what is wrong and leaves the notes
as they are.

Correct spelling, capitalization, and formatting slips directly in the draft
as you go, so the findings list stays focused on substance.

If the requester also wants the problems fixed, switch to writing once the
review is done and correct the entries it found.
